# COROS 自动同步：实施边界与验收

> 2026-10-02：用户明确要求按“首次补历史、后续后台自动更新”的方案修改。此次实现睡眠与运动摘要两个域；原 2026-09-26 仅暂停预览的阶段限制不再代表当前开发授权。其余健康指标仍为后续域。代码完成与后台已启用必须分别报告。

> 2026-10-03：用户将更新频率调整为“每天首次登录工作台时自动触发”。不再每两小时发起新一轮读取；已排队的历史回填、增量补齐和失败重试仍由服务端分批完成。

## 产品行为

- 用户在 Personal Workspace 单独完成一次 COROS OAuth。Codex 插件的现有授权不能转交给工作台。
- 首批自动域：运动活动、主睡眠与小睡、日均/静息心率、步数、压力、睡眠 HRV 和恢复状态的日汇总。经期数据、GPS 原始轨迹与逐秒曲线不纳入。
- 每天首次登录工作台时自动排队一次更新，以工作台时区计算日期，服务端跨设备去重。同一天重复登录不会重复启动一轮更新。排队后的任务由服务端继续处理，关闭浏览器不会丢失进度；未登录的日期不主动开启新一轮更新。MCP 无 webhook，不能承诺实时到达。
- 新增、可稳定识别且字段校验通过的记录自动成为正式 Workout / SleepSession / HealthMetric，不要求每条确认。
- 同一来源 ID 和相同内容的重试是 no-op。相同来源 ID 但内容变化、与手工记录疑似重复、时区或分类不明、字段越界等情况进入待处理区；绝不静默覆盖正式记录。
- 初次连接仍默认暂停。启用时固定首次历史回填的截止日期，在优先更新近期记录的同时分批补齐历史，随后处理每日登录触发的增量；“全部历史”是 COROS 对这些域实际提供且能验证的记录，不扩展到经期、原始 FIT/GPS 或逐秒曲线。历史范围、COROS 可访问的最早日期、预计数量及服务限额必须先以只读方式确认，不能假设所有年代均可通过 MCP 取得。
- 历史回填按 COROS 工具允许的时间窗口分批执行，逐批记入独立游标和计数；失败、暂停或断开后可从最后成功窗口恢复，不能因重试重复创建。活动 FIT 的当前官方限额为固定 24 小时窗口共 50 个文件/链接请求；未经适用许可和容量核对不得把它当作无限量历史通道。
- 回填达到固定截止日期后，按连续增量游标读取之后的未覆盖日期，并有限重查最近数日以接住延迟上传与事后修订。长时间未登录时，先更新近期记录，再分批补齐上次连续完成日期之后的空档，不能只读最近几天而漏掉中间记录。重查不等于重复入库：相同来源 ID + 相同指纹是 no-op，内容变化进入待处理。已完成的历史窗口不常规重扫，只在用户主动修复或来源要求时重跑。暂停、断开、进度、最近成功时间和错误状态必须可见。
- 现有手工与 FIT/TCX 文件导入仍保持逐条确认，不能被自动规则顺带放宽。

## 凭据和授权

- COROS 当前 MCP OAuth 元数据只有通用 `mcp.tools` 等 scope，不能声称远端授权是只读。工作台连接器自身使用硬编码读取工具 allowlist，拒绝所有训练写入工具。
- COROS 官方明确支持 OAuth 个人仪表盘、健康整合以及应用轮询 MCP。本实现仅调用睡眠和运动摘要读取工具。官方另将完整活动传输、双向活动同步、webhook 和 GPX 支持归入 Partner API；不把摘要轮询声称为这些能力，也不绕过访问限制。
- COROS 刷新凭据仅在服务端加密存储；不进入 Private Git、Public Git、浏览器存储或日志。对现有 GitHub 登录的退出语义，需明确区分“退出当前设备”和“断开后台同步”。
- 定时任务还需要**独立的服务端 GitHub 写入身份**；现有浏览器 GitHub token 不能在后台使用。优先评估安装范围仅为 `personal-workspace-data` 的 GitHub App installation token，并最小化 Contents 权限。不得复用用户浏览器 token 或把 PAT 存入代码。
- OAuth 连接、断开和同步控制操作要求已登录用户、同源 CSRF 防护与 GitHub allowlist。调度器不可由公开 HTTP URL 无鉴权触发。

## 数据与事务

- 先固定 COROS 返回结构和单位映射，再为每种域建立版本化映射。只取实现所需的活动摘要、睡眠段及选择的日指标；默认不保存原始 FIT、GPS 轨迹或逐秒曲线。
- 每条候选含 `source_id`、映射版本与规范化内容 SHA-256。正式数据保存来源身份与同步版本，支持可审计的去重与冲突判断。不能以标题、日期或展示文本充当唯一 ID。
- 自动入库的正式记录不能伪称“用户已确认”。Workout 和 Health/Sleep 现有 `confirmation_status: confirmed`、`user_adjusted: true` 等字段需要版本化扩展为 `import_mode: automatic`、`review_status` 等真实语义；旧记录保持可读。
- 创建正式记录与来源索引/审核状态使用同一个带预期 head 的 Git commit；并发失配时重新读取，不回退为多个部分提交。
- 待处理冲突需要明示来源、新旧摘要和原因，但不暴露原始敏感健康载荷到日志。

## 发布闸门

1. 仅用合成数据测试授权状态、自动判定、映射、幂等、并发、撤销、失败重试与导出/恢复。未知字段必须 fail closed。
2. 定时读取仅使用官方 MCP 的个人仪表盘查询能力；本版本不下载 FIT、传输完整活动、写入训练、调用 webhook 或抓取未公开接口。
3. 2026-10-02 已获自动同步实现授权，可添加调度器和自动写入路径。复用工作台独立 OAuth；不从 Codex 导出/复制凭据。后台写入密钥缺失时必须显示未配置并保持暂停，不伪称已在同步。
4. 对真实数据先运行只读预览，核对至少一条运动、睡眠和心率的字段/单位/时区，然后显式启用定时自动入库。
5. 验证断开授权后不再拉取；重新授权不会重复创建；现有已确认 Workout 不会被覆盖。
6. 历史回填先做只读清单：逐域确认最早可用日期、最大查询窗口、页数/截断行为、单位/时区、来源 ID 与预计记录数；只有通过映射和容量验证的域才能启动回填。验证跨窗口重复、延迟上传、源记录修订、速率限制、失败续跑及回填/增量切换。不能以“请求成功”冒充“全量完成”。

## 当前实现与验收状态（2026-10-03 调度调整）

- 工作台独立 OAuth 已存在；连接与最近成功时间以已登录状态接口为准。
- 已实现定时入口、可恢复的分域历史游标、近期优先、指数退避、互斥租约、启用/暂停/断开/请求更新，以及 Pages 同源 COROS 转发。
- 每日首次登录请求由服务端去重排队；调度器每 10 分钟检查待办，每次 scheduled 调用只处理一个来源窗口，避免累计 CPU 成本。首次历史回填截止日期固定，后续按连续游标补齐新增日期；不再每两小时自动开启新的近期查询。睡眠使用三日窗口（真实多日请求发现可能只返回最后三日），运动近期七日、历史最多三十日，返回达到 20 条时自动缩小窗口。无法验证完整性的窗口不推进。
- 2026-10-06 后台补齐直接由 scheduled 入口 await，默认最多一次来源批次尝试、8 分钟启动预算、40 次实际外部 fetch（OAuth、MCP 初始化/读取/清理和 GitHub 均计入）；拒绝自动重定向以免漏计子请求。达到预算时保留已提交批次及加密详情检查点，不新增来源退避，交给下一次 cron。批次内既有 30 秒 HTTP／60 秒 MCP 加最多 4 秒清理期限继续生效，预算到期后不启动后续网络操作；清理阶段耗尽预算不能覆盖真实限流、超时、格式或上游错误；不以 Promise.race 丢弃还在写入的整批任务。
- 每次 cron 核对队列到期、重新读取已提交进度并原子取得原有租约，保持睡眠、运动摘要、HRV、活动汇总、日健康和静息心率六来源公平轮转。HRV 使用独立七日游标和退避；活动续跑不读取 HRV，每批最多读取一项新详情并保存加密断点，未收齐时不扫描 Git、不确认活动 coverage、不写正常续传错误。加密缓存仍限制 256 项，并保留近期／历史两个未完成窗口；缺失爬升或负荷不补零。共享凭据失败仍阻塞所有来源，重新授权只清除已被取代的 invalid_grant 门槛。
- 官方 [Workers limits](https://developers.cloudflare.com/workers/platform/limits/) 与 [Scheduled Handler](https://developers.cloudflare.com/workers/runtime-apis/handlers/scheduled/) 明确 scheduled 墙钟上限 15 分钟，返回的 promise 会被等待；HTTP 响应结束后的 waitUntil 只有 30 秒。CPU 和子请求上限仍由现有套餐决定（十分钟 cron：Paid CPU 30 秒，Free CPU 10 毫秒／外部子请求 50 次），本改动不升级套餐、不提高平台限额、不增加服务或凭据。合成数据验收不能证明生产 CPU 额度或实际全量完成，需发布后按六来源游标和平台执行结果核实。
- 用户主动点击「补齐历史记录」后，前端先排队一次额外请求，再串行调用已登录、同源 CSRF 与固定账户保护的 `/coros/drain`。每次只处理一个窗口，跳过队列等待但保留互斥租约、失败退避和提交前状态检查；完成、错误、暂缓或停止时结束连续调用，关闭页面后调度器仍可续跑。空窗口只推进已验证日期，不读取或提交 Git 健康记录。
- 连续补齐只对 `/coros/drain` 的网络中断、无应用错误码的 502/503/504 及已知 Pages 代理不可用错误最多重试三次，间隔为 1、2、4 秒；不重复初始排队请求。遇到正在占用的后台租约，前端可等待最多十一分钟并显示等待状态，用户可立即停止等待。明确的 COROS 数据、授权或配置错误仍中止，不会将失败当作空记录推进。
- 每次 MCP 读取的连接、工具列表和工具执行共享六十秒总期限，并向实际 HTTP 传输传递取消信号；远端会话终止和本地关闭各最多等待两秒。超时记录受控错误，保留当前日期游标并释放同步租约；清理失败不覆盖已验证的读取结果，也不能无限占用后台任务。
- OAuth 元数据、凭据刷新，以及后台 GitHub installation token 和数据请求，均将响应头与响应体读取纳入每次三十秒期限。OAuth 继续逐块限制最多 64 KiB；超时不会重复发起凭据轮换，也不会被当作无数据推进游标。
- OAuth 既有请求按资源发现、授权服务发现、刷新、注册、兑换分类；失败码仅保留固定阶段、真实 HTTP 数字、缺失正文／网络／超时／解析／容量分类及严格白名单 OAuth error 枚举（如 `COROS_OAUTH_REFRESH_HTTP_400_INVALID_GRANT`）。非 2xx token 响应沿用 64 KiB 与三十秒期限，仅提取枚举；正文不可用时保留已收到的 HTTP 状态。请求／响应正文、token、错误描述、Location 和异常原因不入日志、进度或客户端。普通 HTTP 路由复用受限错误码，客户端仅显示已验证分类。请求数、授权、租约、刷新 CAS、源退避和错误预算不变；不会为诊断主动轮换凭据或清除旧进度。
- 首次启用选择历史开始日期，默认 `2025-05-01`；这只是回填范围，不表示已确认 COROS 最早历史。已读取范围与实际最新记录日期分别显示，不能将二者混淆。
- 已增加版本化文本解析器。只接受已验证格式、单位和时区；格式未知、返回缺日、计数截断和矛盾字段显式失败。自然语言文本不是永久阻碍，但也不作为无限稳定的结构接口。
- 已验证的精确空睡眠提示可在最多三日窗口内表示无记录；更长范围仍拒绝。多日响应缺日或解析失败时，重新查询第一天，仅在单日验证成功后推进一天，不把省略日期推断为无记录。运动显示时长最多容许一秒取整差，规范化活动时长不超过精确 epoch 窗口；更大的差异仍失败。测试样本使用合成数据，不保存账户响应到公共仓库。
- 兼容已核实的旧版仅小睡日期：缺少主睡眠窗口时，评分可省略或为明确的未提供标记 `-1`；后者仍校验每日总时长、阶段比例和清醒字段。两种格式都核对每段小睡与报告总时长，不虚构主睡眠、评分或实际睡着时长。无配速运动允许已验证的心率、热量字段前缀，未知单位与字段仍拒绝。
- 现代仅小睡日期保留每日睡着总时长与时间段总长校验；多段小睡不能从每日总量推算各段睡着时长。明确的 `Sleep Score: 0` 加暂未提供详情提示可代表无记录，不能单凭零评分推断为空。
- 对用户明确授权的旧版小睡年份异常，仅在原始结束年份为 1982、月日与睡眠归属日一致且含旧版总时长标记时，按归属日修正年份；原始开始只允许同一日或前一日，跨午夜关系保持不变。时刻、时区、时长保持不变，继续校验重叠与总时长；保存原始起止时间及修正原因，并在健康记录页明确标注。其他年份、跨多日或不一致日期不猜测修复。修正证据参与内容指纹并保留于导出与冲突记录。
- 自动记录使用兼容旧数据的 v2 格式，来源与校验状态明确，绝不伪装成用户确认。手工睡眠冲突、来源修订保存候选供核对；FIT 同时间运动避免重复。记录、冲突和派生索引由同一个带预期 HEAD 的 Git commit 保存。
- 派生索引逐条对照 Git blob SHA，每轮只读取变化的正式记录；健康列表与导出支持超过 1,000 个文件。派生索引不进入可移植备份，恢复后重建。
- 服务端 GitHub App 私钥通过一次性配置脚本读取本机 PEM、校验身份并上传 Worker Secret，不输出密钥。现有公开 App/installation/account/owner 标识已固定，凭据未就绪时不允许启用。
- 本次新增单元与事务测试全部使用合成数据；真实 MCP 只读核对不写入测试或公共代码。部署、正式启用和首次真实写入的完成情况应以最终发布记录及页面状态为准。
