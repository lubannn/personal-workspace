# Phase 2A：Tasks 基础闭环

> 状态：首个垂直切片已通过正式环境跨设备验收  
> 日期：2026-08-28

## 1. 本切片目标

建立最小但真实可用的任务闭环：

1. 在任意已登录设备创建任务；
2. 今日 Dashboard 展示今天到期和已经逾期的未完成任务；
3. 用户可以完成任务，也可以从已完成视图恢复为待办；
4. 所有状态跨设备同步，且并发更新不静默覆盖；
5. Task 进入开放 JSON 导出、完整性预检、schema dry run 和隔离恢复。

本切片不实现编辑详情、取消、归档、软删除、项目关联、子任务、时间记录和 Calendar 时间块；这些在后续 Task/Project/Calendar 切片逐步开放。

## 2. Canonical 文件

每个 Task 使用独立开放 JSON 文件：

```text
data/tasks/<task_id>.json
```

记录沿用通用 envelope：`schema_version`、`entity_type`、`id`、`owner_id`、`version`、创建/更新时间、`deleted_at` 与 `data`。

`data` 保留完整 Phase 2 字段基础：

- 标题、分类、状态、优先级；
- Project 与父任务引用；
- 计划开始/结束、DDL、时区和 date-only 标记；
- 预计/实际耗时、标签、Markdown notes；
- 完成与取消时间。

工作、生活、人生是初始分类代码，不依赖界面文案解析。

## 3. 状态与并发规则

- 新任务初始为 `todo`；完成后为 `done` 并写入 `completed_at`。
- 从完成状态恢复时清除当前 `completed_at`，历史版本仍保留在 Git。
- 每次更新增加记录 `version`。
- 更新请求携带读取时的 Git blob SHA；另一设备先写入时，GitHub 拒绝陈旧更新并要求刷新。
- 任务正文不进入 LocalStorage；页面刷新后重新从 Private GitHub 读取。

## 4. Today 规则

本切片把下列开放任务纳入“今日待办”：

- `due_at` 是今天；
- `due_at` 早于今天，即已经逾期。

未来日期和无 DDL 任务保留在完整任务清单中，不进入 Today。排序先按 DDL，再按优先级，最后按创建时间。

## 5. 验收标准

- 创建任务后，Private 仓库出现一个合法 `data/tasks/*.json` 文件。
- 今天到期的任务立即出现在 Dashboard 与任务清单。
- 完成后从待办移入已完成；恢复后重新进入待办。
- 另一设备刷新后能读取同一状态，并能执行一次反向状态更新。
- 并发陈旧写入显示冲突，不覆盖新版本。
- 开放导出中的文件总数和 Task 数量正确，恢复预检通过。
- 自动测试、类型检查、Lint 和生产构建通过。
