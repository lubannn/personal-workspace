# 通告

「通告」与现有主导航平级，用于少量近期需要反复查看的纯文本提醒。
独立卡片采用 24–34px 字号、明显边线和间距；保留换行，长词可换行，操作按钮至少 44px 高。
仅提供新增、编辑、软删除、回收站恢复和刷新。单条最多 4,000 个字符，最新创建的通告排在前面。

## 存储与兼容

记录沿用 schema_version 1 的 WorkspaceRecord，entity_type 为 `notice`，
正文位于 `data.body`，文件为 `data/notices/<id>.json`。
读写复用当前经过 Private 检查和身份认证的 GitHubContentsAdapter。
编辑、删除和恢复携带已读取的 blob SHA，冲突时不覆盖远端内容。
普通浏览只读；未访问通告时不加载该集合；旧仓库缺少该目录时显示空白模块，不自动创建文件。
正文和未提交输入仅保留于当前页面内存，不作为浏览器持久数据保存。退出连接清理记录和提交状态。

保存期间拦截重复提交，失败时保留输入。重试使用相同记录 ID、时间戳；
写响应丢失时，仅在远端正文与本次完整序列化记录完全一致的情况下确认成功。
真正的冲突需刷新核对后重新打开编辑，草稿不会自动覆盖新版本。
输入通过 React 文本节点显示，HTML、Markdown 都按字面显示。

完整 JSON 导出包含有效和已删除的通告、manifest 数量与 SHA-256 校验。
恢复预检检查记录结构、所有者、路径和数量；复用原有隔离 Private 仓库原子恢复约定。
没有通告 scope/count 的旧导出仍可通过预检；已有业务记录不需要迁移或重写。
